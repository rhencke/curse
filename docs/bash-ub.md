# bash undefined behaviour: documented, not mimicked

curse is bug-for-bug compatible with bash 5.2.21: every *defined* bash behaviour, bugs
included, is reproduced (the conformance oracle is the in-tree 5.2.21 build). The one
exception is behaviour that exists only because bash hits C **undefined behaviour**
(out-of-bounds or uninitialized reads, overflows, bad pointers). Its outcome depends on
heap/stack contents, so bash itself varies between runs, builds and contexts; copying
it would mean shipping UB (and possible security holes). For each such case curse picks
one sane, deterministic behaviour, documented here and pinned by `test/ub/`.

How a case qualifies: the bash source shows the UB, and the pinned oracle's output is
not stable across runs or contexts. A merely *odd* but deterministic bash behaviour is
a quirk and must be copied — it doesn't belong here.

| Case | bash 5.2.21 source | Why it is UB | curse's choice | Pinned by |
|---|---|---|---|---|
| `jobs %spec` where the spec is ambiguous (e.g. `%sleep` with two sleep jobs) | builtins/jobs.def `jobs_builtin`: `get_job_spec` returns `DUP_JOB` (-2); `get_job_by_jid(job) == 0` with `#define get_job_by_jid(ind) (jobs[(ind)])` (jobs.h:91) | reads `jobs[-2]`, the word before the job array (glibc: the previous heap chunk's tail), so "no such job" + status 1 appear only when that word happens to be 0. It follows the heap history — even the environment — not the syntactic context. Probed on the pinned 5.2.21: a three-line script gives status 1 at top level, in a function and in a loop (test/ub/jobs-dupjob-small.sh); test/ub/jobs-dupjob.sh gives 0; test/cases/1820 gives 0 run by hand but 1 under `meson test`'s environment, so no case can compare it with the oracle | bash's outcome in small scripts (top level, function and loop alike): "ambiguous job spec" and "%spec: no such job", status 1, in every context. (`kill`/`wait`/`disown`/`fg`/`bg` check `INVALID_JOB()` or `j < 0` first — deterministic, copied exactly; see test/cases/2525) | test/ub/jobs-dupjob.sh (bash there: 0), test/ub/jobs-dupjob-small.sh (bash there: 1) |
| Word splitting when IFS is not valid text in the locale and a pending `mbtowc` character completes on the unquoted IFS[0] between quoted elements | subst.c `string_extract_verbatim` / `list_string`: `wcschr(wcharlist, wc)` | `mbstowcs` failed, leaving `wcharlist` uninitialized heap memory | IFS taken as holding nothing (the elements are joined by IFS[0], not split) | test/ub/ifs-mb-wcharlist.sh (lua/runtime.lua FB:multi) |
| IFS whose first character is longer than the current `MB_CUR_MAX` (IFS set under a UTF-8 locale, then `LC_ALL=C`) | subst.c: `char sep[MB_CUR_MAX+1]` filled from `ifs_firstc` | stack buffer overflow | the first character is used whole (`"$*"` joins with all its bytes) | test/ub/ifs-sep-overflow.sh |
| Unbounded recursion: a function calling itself without end (`f() { f; }; f`), or a trap handler that re-raises its own signal (`trap 'kill -USR1 $BASHPID' USR1`) | execute_cmd.c `execute_function` → `execute_command_internal` → … (no depth limit unless `FUNCNEST` is set); trap.c `run_pending_traps` → `_run_trap_internal` → `parse_and_execute` (a trap on the signal being handled runs again, nested) | every level takes C stack until it runs out: SIGSEGV (status 139, the shell's own EXIT trap never runs); with a subshell between the signals (`trap '( kill -USR1 $$ )' USR1`) the nesting instead depends on signal timing — under the AFL fuzzer it ran on past a 5 s limit in one run and ended at once in another | the shell running the recursion — the script, or a subshell / `$(…)` / job, which curse runs in-process — stops with `NAME: stack overflow` (no line: where LuaJIT's stack gives out differs by tier), status 1, as a crashed child stops alone; a script's EXIT trap still runs. (`rt.lua_overflow`, at `interp.finish` and each in-process subshell boundary: only LuaJIT's own `stack overflow` error is taken there — any other internal error still escapes, so a bug is not hidden) | test/ub/recursion.sh |
| `${ref:=word}` / `${ref=word}` through a nameref to an array element (`declare -n ref='a[5]'`) when the array has no element 0 | subst.c `parameter_brace_expand_rhs`: `vname` is the nameref's own name (not a `valid_array_reference`), so `bind_variable` assigns the element through the nameref and returns the ARRAY; then `t1 = get_variable_value (v)` — `array_reference (a, 0)` — and `quote_string (t1)` | with no element 0, `get_variable_value` returns NULL and `quote_string` dereferences it: SIGSEGV. (With an element 0 bash deterministically substitutes ITS value, not the assigned one — a quirk curse copies: test/cases/2911) | the assigned element's stored value is substituted (the -i/-u/-l attributes applied), in every tier | test/ub/nameref-elem-assign-default.sh |
| `declare -g NAME+=(…)` (or `typeset -g`) in a function over a global associative array NAME | subst.c `do_compound_assignment` (mkglobal): `else if (v && mkassoc == 0 && array_p (v) == 0) v = convert_var_to_array (v);` — arrayfunc.c `convert_var_to_array`: `oldval = value_cell (var); … array_insert (array, 0, oldval)` | for an associative array `value_cell` is its HASH_TABLE pointer, read as a C string: element 0 gets whatever bytes the heap holds there (differs run to run) before the quoted words are appended. (With `=` the array is emptied first, so the result is deterministic — the words keep the quotes the associative expansion gave them: a quirk curse copies, test/cases/2915) | the converted array starts empty; the words, quoted as bash stores them, are appended | test/ub/declare-g-append-assoc.sh |
| printf text past INT_MAX bytes: a `*` precision of exactly INT_MAX (`printf '%.*f' 2147483647 1`), or `printf -v` with a text over INT_MAX (a `*` width or precision near INT_MAX) | builtins/printf.def: `PF` calls glibc `printf`/`vsnprintf`, whose byte count is an `int`; `vbprintf` adds `vsnprintf`'s return to `vblen` unchecked, and `vbadd` sizes its buffer in an `int` (`vbsize = ((vblen + blen) + 64) & ~63`) | glibc's counts overflow: at precision INT_MAX stdout gets INT_MAX spaces before the number (4 GiB); `vsnprintf` fails with -1 (EOVERFLOW), which bash uses as a length — `printf -v` keeps the buffer's leftovers (15 spaces; `acd` from `ab%.*fcd`); a huge `*` width overflows `vbadd`'s signed size — `xrealloc: cannot allocate 18446744071562067968 bytes`, fatal (status 2). (A text under INT_MAX is written exactly: copied, test/cases/2921 — but glibc builds it in one buffer, so near INT_MAX (2 GiB) bash's output depends on the memory it can get: with less, glibc fails and nothing is printed. That resource failure is not copied; curse streams the exact text in constant memory.) | stdout: the exact text, streamed; `printf -v` over INT_MAX: `xrealloc: cannot allocate N bytes` with the true size, fatal, status 2 (a subshell's alone) | test/ub/printf-int-overflow.sh |
| Recursion deep enough to exhaust bash's own resources, though it would end: a function, `eval`, `source`, subshell or `$(…)` calling itself thousands of levels deep | execute_cmd.c `execute_function` / builtins/evalstring.c `parse_and_execute` / `source_file`: every level takes C stack, with no limit but `$FUNCNEST`; a `( … )` or `$(…)` level is a forked process that inherits the deep stack | measured on the pinned 5.2.21 under `tools/capped` (8 MiB stack): a function recursion is fine at 6781 levels and dies of SIGSEGV (139) by 6830, `eval` 5464 / 5513, `source` 5562 / 5610; a subshell recursion is bounded by processes (TasksMax: `fork: retry: Resource temporarily unavailable`, then a failed fork) and memory (every level's process holds its own copy of the stack it grew: 1000 nested subshells 3000 deep in functions filled a 3 GB cgroup); a `$(…)` recursion costs quadratic time (900 levels: 26 s) before either | everything bash completes, curse completes: each nesting level (rt.nest_pcall / rt.ncall) runs on a fresh coroutine every 32 levels, so LuaJIT's 65500-slot stack no longer limits it; past RLIMIT_STACK/600 levels (8 MiB: 13981 — beyond every point where bash has crashed) it stops with `stack overflow`, status 1, as in the row above; with an unlimited stack only memory bounds it (next row) | test/cases/3367-deep-bounded-recursion.sh, test/ub/recursion.sh |
| Running out of memory | xmalloc.c `allocerr`: `fatal_error ("%s: cannot allocate %lu bytes", func, bytes)`, then `sh_exit (2)` | not UB — but the byte count is the size of the one request that failed, which depends on bash's allocator and growth policy (`xmalloc` or `xrealloc`, and how far a buffer had grown); curse's heap (LuaJIT's) never asks for the same sizes | `NAME: xmalloc: cannot allocate N bytes` (no line), status 2, where N is the heap curse held when the allocation failed; the shell exits at once (no EXIT trap, as bash's `sh_exit`); an in-process subshell or `$(…)` ends alone, status 2 (rt.oom) | test/cases/3366-out-of-memory-status.sh (N masked) |
